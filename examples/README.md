# Examples

Three scenes an agent actually authored with this server, kept as their **hand-written sources only**.

| | what it shows | hand-written source |
|---|---|---|
| [SkylineBoulevard](SkylineBoulevard) | a procedural downtown boulevard — 300 KB of SSDL from 42 KB of Python | `gen_tex.py`, `gen_city.py` |
| [ShenzhenNorthStation](ShenzhenNorthStation) | a real station rebuilt to published railway dimensions, tuned against aerial reference | `gen_tex.py`, `gen_station.py` |
| [DuskRange](DuskRange) | a playable 75-second shooting range: keyboard input, hit scoring, HUD, collision | `scene.ssdl`, `Camp.ssdl`, `logic.mjs` |

What is **not** here, on purpose: `scene.ir.json`, `scene.generated.mjs`, the page shell, and the
textures. Those are all build products — the two city scenes generate both their textures *and*
their `scene.ssdl` from the Python scripts, deterministically (re-running is byte-identical), so
shipping them would be shipping the same information twice. Each example is under 250 KB.

## Running one

```bash
# 1. let the server create the project (this writes the page shell)
#    via your agent:  ssworld_project_create { name: "SkylineBoulevard", lon: ..., lat: ... }
# 2. copy this directory's files over it
cp -r SkylineBoulevard/* ~/.ssworld/projects/SkylineBoulevard/
# 3. run the generators named in the project's own README
cd ~/.ssworld/projects/SkylineBoulevard && python gen_tex.py && python gen_city.py
# 4. back in your agent:  ssworld_compile  then  ssworld_preview
```

Each project's `README.md` carries its own reproduce steps, structure notes and honest limits.

## Assets and licensing

Every texture and mesh in these three is generated by the scripts in the example itself — no
third-party models, no external downloads. Scenes that do use third-party assets live in the
showcase repository with their attribution, and are not bundled here.
